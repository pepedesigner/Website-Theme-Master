Intro

SandCode is flat-rate coding compute for agent clients. The gateway speaks both the OpenAI and Anthropic wire formats, so any client that accepts a custom base URL can draw on your pool — with search, scrape and a local verification harness layered on top.

Quickstart

Install the CLI, then run the setup wizard. It detects every client on your machine, links your account, writes the endpoint and injects the MCP tools.

curl -fsSL https://sandcode.ai/install | bash
# or
npm i -g sandbase-ai
brew install sandbase/tap/sandbase
paru -S sandbase
sandbase setup

Setup asks before touching any config file, and every credential it writes is a short-lived, revocable token — never a long-lived secret sitting in a file that may be synced or committed. It finishes by running one live request, a search for the current version of a dependency, so your first task is a real one and you can watch the meters move.

Configure

Point your client at the unified base URL and authenticate with a key from the Console.

Base URL   https://api.sandbase.ai/v1
Auth       Authorization: Bearer sb_live_<key>

POST /v1/chat/completions        # OpenAI-compatible
POST /v1/messages                # Anthropic-compatible
POST /v1/messages/count_tokens   # required by Claude Code
curl https://api.sandbase.ai/v1/chat/completions \
  -H "Authorization: Bearer sb_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek/deepseek-v4.1-flash",
       "messages":[{"role":"user","content":"hi"}]}'

The Anthropic side is a full implementation, not a shim: streaming events, stop_reason, thinking blocks with a stable signature, multimodal content and token counting are all mapped. The token-counting endpoint is not optional — Claude Code calls it to budget context, and a client that gets an error here behaves strangely.

Rotate or revoke keys at any time. Keys are bound to the account, a device fingerprint and your concurrency limit:

sandbase auth rotate

Eight models, priced at upstream list rate with prompt-caching discounts passed through 1:1. Four draw on the full monthly pool; the two flagship reasoning models sit behind a smaller monthly sub-quota so long-thinking arbitrage cannot eat the shared pool.

Tools

Search and scrape are injected as MCP tools during setup, so the agent can look things up mid-task instead of inventing an API.

ToolBacking APIsStandard quota
Searchcloudsway/search, exa/search500 calls/month
Scrapefirecrawl/scrape, exa/contents500 calls/month
GitHubsandbase/githubNot counted against the quota

Limits: 30 tool calls per minute with at most 2 in flight. Beyond the included quota, calls are billed at $0.02 each. Setup writes these entries into the MCP config of every client it finds.

Harness

The harness is a local MCP server installed on your machine. It never runs on our side, because the gateway has no access to your filesystem, tests or Git repository.

CapabilityWhat it does
Syntax checkValidates the change as it lands. Clients with a pre-write hook can block it; others verify immediately after and roll back on failure.
Test hooksRuns the relevant tests after each edit — pytest, jest or cargo test.
Self-healFeeds the failure back to the model for up to 3 rounds.
RollbackIf it still fails, the Git working tree is restored so a bad edit cannot spread.

It needs explicit consent at setup, reads your project directory only for the checks above, and reports back only usage metadata. Turn it off whenever you like:

sandbase harness off

Sandbox isolation of the local environment stays your responsibility.

Rules & Skills Sync

Project conventions live in one file you version and review, then compile out to each client's native format.

# .sandbase/rules.md is the source of truth
sandbase rules sync
# -> .cursorrules, CLAUDE.md, opencode.json

Because the rules are declarative and committed, they can be reviewed in a diff and shared across a team — unlike preferences learned into an opaque model.

Migrate

Coming from another agent? The migration command scans local config for OpenCode or Command Code, backs it up, and rewrites it to use your SandCode credentials. A successful migration ends on a share card carrying your invite code.

sandbase migrate --from opencode
sandbase migrate --from commandcode

Status & traces

Check your windows and meters from the terminal, or inspect a session in detail.

sandbase status
sandbase trace --last

The status command shows the 6h window, the reasoning sub-quota, separate search and scrape meters, harness state and the PAYG wallet balance. The trace command shows per-request tokens, cache hit ratio, tool latency and decision steps for sessions you have opted into tracing.

Errors & limits

SituationStatusResponse
Monthly pool exhausted402Retry hint plus a top-up link
6h or weekly window exhausted402The time the window releases
Burst rate limit hit429Retry-After header
More than 5 concurrent requests429Retry-After: 1
All upstreams unavailable503Degraded notice, survival tier engaged

Quota exhaustion is deliberately 402, never 429. Clients retry 429 automatically, so signalling "out of quota" that way would create a retry storm rather than telling you to top up. If every upstream fails, requests fall back to the free survival tier — the preview model at 3 requests per minute, capped at 60 per day — which is not covered by the SLA.

Data & retention

Requests are never used for training. Retention is tiered rather than absolute — a full session trace and "nothing is ever stored" cannot both be true, so we are specific about each class of data.

DataDefaultKept for
Token ledger and call metadataStored (required for billing)24 months
Tool-call records (query, URL)Stored, you can turn it off90 days
Prompt content and model outputNot stored7 days if you opt in
Thinking chain and decision traceNot stored7 days if you opt in (Pro and Team)
Code snippets for dependency checksIn memory only—

Anything you opt into is redacted before storage, can be deleted in one action, and can be excluded from specific regions. Enterprise customers can request data-residency options and a DPA.
